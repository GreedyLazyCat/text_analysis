# Классификация новостных текстов по стилометрическим признакам

Проект собирает новости с сайтов РИА Новости и «Газета.Ru», преобразует тексты в набор количественных стилометрических признаков и обучает классификатор, который отличает тексты двух источников/периодов.

Основной сценарий запуска находится в `main.py`.

## Что делает программа

Полный конвейер выглядит так:

1. `RecentNewsParser` собирает новости РИА Новости.
2. `OldNewsParser` собирает новости «Газета.Ru» за период, заданный URL поиска.
3. Для каждой статьи извлекаются заголовок, текст, дата и ссылка.
4. Текст проходит предварительную очистку в соответствующем парсере.
5. `StylometricAnalyzer` вычисляет стилометрические характеристики.
6. Обработанные статьи сохраняются в `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.
7. `NewsClassifier` читает эти файлы, превращает стилометрию в числовые векторы и обучает классификатор Gaussian Naive Bayes.
8. Для тестовой выборки вычисляется accuracy, затем модель делает пример предсказания и возвращает вероятности классов.

## Какие тексты используются

### РИА Новости

`main.py` передаёт парсеру адрес `https://ria.ru/politics/`. Selenium открывает страницу в headless-режиме, выбирает весь доступный период и нажимает кнопку загрузки дополнительных материалов не более 15 раз. Затем для каждой найденной ссылки открывается полная статья.

### «Газета.Ru»

Используется URL поиска с периодом с `2003-01-01` по `2008-01-01`. Парсер нажимает кнопку «Показать ещё» не более 20 раз, извлекает ссылки на статьи и затем открывает каждую статью отдельно.

Фактический состав обучающей выборки определяется тем, какие материалы удалось скачать при запуске. Результаты парсинга хранятся в папке `data`: `data/ria.csv`, `data/gazeta.csv`, `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.

## Предварительная обработка текста

Предварительная обработка выполняется в методе `process_text` каждого парсера. Она происходит **до** вызова стилометрического анализа.

### Обработка РИА Новости

В `recent_news.py`:

1. Текст разбивается на токены с помощью `razdel.tokenize`.
2. Все токены переводятся в нижний регистр.
3. Оставляются только токены, для которых `isalpha()` возвращает `True`. Поэтому числа, пунктуация, URL и смешанные буквенно-цифровые фрагменты удаляются.
4. Удаляются слова из небольшого вручную заданного списка стоп-слов, в основном формы слов «который», «этот», «весь», «свой».
5. С помощью `pymorphy3` каждое слово приводится к нормальной форме (лемме). Берётся первый вариант разбора: `parse(token)[0].normal_form`.
6. К лемме применяется русский Snowball stemmer.
7. Стемы объединяются в одну строку через пробел.

### Обработка «Газеты.Ru»

В `old_news.py` используется почти такой же порядок:

1. `nltk.word_tokenize` разбивает текст после перевода в нижний регистр.
2. Удаляются все неалфавитные токены и слова из значительно более широкого списка русских стоп-слов.
3. `pymorphy3` выполняет лемматизацию, также выбирается первый морфологический разбор.
4. К леммам применяется `SnowballStemmer("russian")`.
5. Полученные стемы соединяются пробелами.

### Важное следствие

В CSV поле `text` уже содержит не исходный русский текст, а последовательность стемов, например `тысяч сторонник погибш ...`. Это означает, что исходная пунктуация, регистр, цифры и большинство служебных слов к моменту стилометрии уже потеряны.

Кроме того, очистка для двух источников неодинакова:

- РИА Новости использует небольшой список стоп-слов и `razdel`;
- «Газета.Ru» использует большой список стоп-слов и `nltk.word_tokenize`.

Поэтому часть различий, которые классификатор принимает за особенности источника или периода, может быть вызвана не самим авторским стилем, а разными правилами подготовки данных.

## Какие параметры вычисляет стилометрия

Класс `StylometricAnalyzer` в `stylometry.py` получает уже обработанную строку и вычисляет следующие характеристики. Важно: внутри `analyze` он снова вызывает морфологический анализатор для уже усечённых стемов. Поэтому для лексической плотности и POS-биграмм используются результаты разбора стемов, а не исходных слов.

### 1. Частоты русских букв

Метод `char_frequencies`:

- переводит текст в нижний регистр;
- оставляет только символы русского алфавита `[а-яё]`;
- считает каждую букву;
- делит количество буквы на общее количество русских букв;
- округляет частоты до 4 знаков после запятой.

Результат имеет вид `{буква: относительная_частота}`. Пунктуация и латинские буквы в этот признак не входят.

### 2. Средняя длина предложения

Метод `avg_sentence_length` разбивает текст на предложения через `razdel.sentenize`. Для каждого предложения считает только токены, удовлетворяющие `isalpha()`, и возвращает среднее число слов в предложении. Результат округляется до 2 знаков.

Поскольку вход уже был превращён в строку стемов без пунктуации, границы предложений обычно утрачены. В таком случае весь текст может рассматриваться как одно предложение, а показатель фактически становится близок к количеству слов в статье.

### 3. Средняя длина слова

Метод `avg_word_length` считает среднее количество символов в токенах:

```text
сумма длин токенов / количество токенов
```

Результат округляется до 2 знаков.

### 4. Лексическая плотность

Сначала токены из уже обработанного текста (то есть стемы) повторно анализируются морфологически. К содержательным частям речи относятся:

- `NOUN` — существительные;
- `ADJF` — полные прилагательные;
- `VERB` — глаголы;
- `ADVB` — наречия.

Показатель равен доле таких слов среди всех лемм и округляется до 4 знаков:

```text
число содержательных слов / число всех лемм
```

### 5. Лексическое разнообразие

Метод `lexical_diversity` вычисляет:

```text
число уникальных лемм / число всех лемм
```

Результат округляется до 4 знаков. В `analyze` список `lemmas` формально получает результаты `normal_form` для стемов, поэтому это не обязательно леммы исходных слов.

### 6. Биграммы частей речи

Для каждого обработанного токена-стема определяется часть речи через `pymorphy3`. Для последовательности POS-тегов строятся биграммы, то есть пары соседних тегов (`n=2`). Например, пара может соответствовать последовательности «существительное + глагол». Поскольку стемы могут быть неполными словами, часть разборов может быть неточной или не иметь POS-тега.

В результат записывается словарь:

```text
{(POS_1, POS_2): количество появлений}
```

Это **абсолютные количества**, а не нормированные частоты. Если в тексте меньше двух POS-тегов, словарь пуст.

## Как из стилометрии формируется вектор признаков

Классификатор не передаёт весь JSON напрямую в модель. Метод `NewsClassifier.extract_features` строит фиксированный вектор из 19 чисел:

| Позиции | Признак |
|---:|---|
| 1 | средняя длина предложения |
| 2 | средняя длина слова |
| 3 | лексическая плотность |
| 4 | лексическое разнообразие |
| 5–14 | значения 10 самых частотных букв |
| 15–19 | значения 5 самых частотных POS-биграмм |

Для букв берутся пары из `char_frequencies`, отсортированные по убыванию частоты. Для POS-биграмм выполняется такая же сортировка по абсолютному количеству появлений. Если в конкретном тексте меньше 10 букв или меньше 5 биграмм, вектор дополняется нулями.

### Ограничение текущего представления

В вектор записываются только **значения** частот/счётчиков, но не названия букв и не сами POS-биграммы. Например, модель получает `0.15`, но не получает информацию о том, что это частота буквы `о`. Поэтому признак на позиции 5 не означает одну и ту же букву для всех текстов: на этой позиции находится частота первой по частотности буквы конкретной статьи.

Из-за этого два текста могут иметь одинаковый набор чисел, но эти числа могут относиться к разным буквам или разным POS-парам. Это снижает интерпретируемость и может ухудшать качество классификации.

## Как выполняется классификация

В `main.py` вызывается:

```python
accuracy = classifier.train("data/gazeta_analyzed.csv", "data/ria_analyzed.csv")
```

Внутри `train`:

1. Из `data/gazeta_analyzed.csv` извлекаются стилометрические данные, всем строкам назначается метка `0`.
2. Из `data/ria_analyzed.csv` извлекаются данные, всем строкам назначается метка `1`.
3. Данные объединяются в матрицу `X`, метки — в массив `y`.
4. `train_test_split` делит данные на обучающую и тестовую части. Размер тестовой части — `20%` (`test_size=0.2`), `random_state=42`.
5. На обучающей части обучается `GaussianNB` из scikit-learn — гауссовский наивный байесовский классификатор.
6. На тестовой части считается `accuracy`, то есть доля правильных предсказаний.

Таким образом, классы в текущем коде означают:

- `0` — строка из `data/gazeta_analyzed.csv`, вывод программы называет её «Старая» новость;
- `1` — строка из `data/ria_analyzed.csv`, вывод программы называет её «Новая» новость.

Строго говоря, модель обучается различать не абстрактную «новизну», а два набора данных: «Газета.Ru» против РИА Новости. Источник и временной период смешаны в одном признаке класса, поэтому по результату нельзя надёжно утверждать, что модель распознаёт именно дату новости.

Для нового текста сначала нужно получить стилометрический JSON того же формата, затем вызвать:

```python
prediction = classifier.predict(stylometry_data)
probabilities = classifier.predict_proba(stylometry_data)
```

`predict` возвращает `0` или `1`, а `predict_proba` — вероятности обоих классов.

## Формат файлов

- `data/ria.csv` — скачанные статьи РИА Новости до стилометрии.
- `data/gazeta.csv` — скачанные статьи «Газеты.Ru» до стилометрии.
- `data/ria_analyzed.csv` — текст и JSON со стилометрическими признаками РИА Новости.
- `data/gazeta_analyzed.csv` — текст и JSON со стилометрическими признаками «Газеты.Ru».
- `stylometry.py` — вычисление признаков.
- `classifier.py` — подготовка векторов, обучение и предсказание.
- `recent_news.py` — сбор и предварительная обработка РИА Новости.
- `old_news.py` — сбор и предварительная обработка «Газеты.Ru».
- `main.py` — полный сценарий.

## Запуск

Зависимости перечислены в `requirements.txt`. Для запуска полного цикла:

```bash
python main.py
```

При запуске программа спрашивает:

```text
Парсить новости заново? [д/н]:
```

- `д`/`да` — заново открыть сайты, скачать статьи, выполнить их предварительную обработку и пересчитать стилометрию. Файлы `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv` будут перезаписаны.
- `н`/`нет` — не обращаться к сайтам, а использовать уже подготовленные `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.

В режиме готовых данных оба CSV-файла должны находиться в папке `data`. Если хотя бы одного файла нет, программа завершится с сообщением о том, какой файл нужно добавить или выбрать режим нового парсинга.

Для работы парсеров требуется установленный Chrome/Chromium и возможность Selenium запустить браузер в headless-режиме. `webdriver-manager` автоматически подбирает ChromeDriver в используемом сценарии РИА Новости; для «Газеты.Ru» Selenium использует доступный драйвер Chrome.

## Методологические замечания

- Классификация выполняется на уровне источников/наборов данных, а не на уровне авторов.
- Предварительная обработка удаляет пунктуацию, поэтому часть синтаксических стилометрических признаков теряет смысл.
- Разные источники обрабатываются разными токенизаторами и списками стоп-слов.
- POS-биграммы представлены абсолютными счётчиками, поэтому они зависят от длины текста.
- Деление на train/test выполняется случайно с фиксированным seed, но в коде нет стратификации и кросс-валидации.
- Одной `accuracy` недостаточно для полноценной оценки: при несбалансированных классах следует дополнительно смотреть precision, recall, F1 и confusion matrix.
