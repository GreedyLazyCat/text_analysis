# Классификация новостных текстов по стилометрическим признакам

Проект собирает новости с сайтов РИА Новости и «Газета.Ru», сохраняет исходный корпус, преобразует тексты в набор количественных стилометрических признаков и обучает классификатор, который различает два набора данных.

Основной сценарий запуска находится в `main.py`.

## Что делает программа

Полный конвейер состоит из трёх независимых этапов:

1. `RecentNewsParser` собирает новости РИА Новости.
2. `OldNewsParser` собирает новости «Газета.Ru» за период, заданный URL поиска.
3. Для каждой статьи извлекаются заголовок, текст, дата и ссылка.
4. Парсеры сохраняют исходный текст статьи без стемминга и удаления стоп-слов.
5. Исходный корпус сохраняется в `data/ria.csv` и `data/gazeta.csv`.
6. `StylometricAnalyzer` читает исходный корпус и вычисляет стилометрические характеристики.
7. Результаты анализа сохраняются в `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.
8. `NewsClassifier` превращает стилометрию в числовые векторы и обучает Gaussian Naive Bayes.
9. Данные делятся на train/test, вычисляется `accuracy`, состав выборок сохраняется в `data/classifier_split.json`.
10. Демонстрационное предсказание выполняется для записи из test-выборки.

## Какие тексты используются

### РИА Новости

`main.py` передаёт парсеру адрес `https://ria.ru/politics/`. Selenium открывает страницу в headless-режиме, выбирает весь доступный период и нажимает кнопку загрузки дополнительных материалов не более 15 раз. Затем для каждой найденной ссылки открывается полная статья.

### «Газета.Ru»

Используется URL поиска с периодом с `2003-01-01` по `2008-01-01`. Парсер нажимает кнопку «Показать ещё» не более 20 раз, извлекает ссылки на статьи и затем открывает каждую статью отдельно.

Фактический состав корпуса определяется тем, какие материалы удалось скачать при запуске. Исходные тексты хранятся в `data/ria.csv` и `data/gazeta.csv`, а рассчитанные для них признаки — в `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.

## Предварительная обработка текста

Парсеры только извлекают текст и сохраняют его с пунктуацией. Единая токенизация, лемматизация и POS-анализ выполняются позже внутри `StylometricAnalyzer`, поэтому оба источника проходят одинаковую обработку.

### Обработка РИА Новости

В `recent_news.py` текст извлекается из блоков статьи и сохраняется без удаления пунктуации, регистра и чисел. Сам парсер не выполняет стилометрическую предобработку.

1. Исходный текст сохраняется как есть.
2. Для лингвистических признаков он токенизируется через `nltk.word_tokenize`.
3. В анализ слов включаются все алфавитные токены, включая стоп-слова.
4. `pymorphy3` получает исходные слова, а не стемы.

### Обработка «Газеты.Ru»

В `old_news.py` текст всех найденных абзацев объединяется и сохраняется без стилометрической предобработки.

1. Исходный текст сохраняется с пунктуацией.
2. Для анализа используются те же `nltk.word_tokenize`/`nltk.sent_tokenize` и тот же морфологический анализатор.
3. Стоп-слова не удаляются, а стемминг не применяется: исходные слова не заменяются укороченными формами.

### Важное следствие

В CSV поле `text` содержит исходный текст. Поэтому сохраняются границы предложений, пунктуация, регистр, числа и служебные слова. Оба источника используют одинаковые правила анализа, что уменьшает влияние технических различий preprocessing на классификацию.

## Какие параметры вычисляет стилометрия

Класс `StylometricAnalyzer` в `stylometry.py` получает исходный текст и вычисляет следующие характеристики.

### 1. Частоты русских букв

Метод `char_frequencies`:

- переводит текст в нижний регистр;
- оставляет только символы русского алфавита `[а-яё]`;
- считает каждую букву;
- делит количество буквы на общее количество русских букв;
- округляет частоты до 4 знаков после запятой.

Результат имеет вид `{буква: относительная_частота}`. Пунктуация и латинские буквы в этот признак не входят.

### 2. Средняя длина предложения

Метод `avg_sentence_length` разбивает текст на предложения через `nltk.sent_tokenize`. Для каждого предложения считает только токены `nltk.word_tokenize`, удовлетворяющие `isalpha()`, и возвращает среднее число слов в предложении. Результат округляется до 2 знаков.

Поскольку анализ получает исходный текст, `nltk.sent_tokenize` видит реальные границы предложений. Показатель больше не заменяется приблизительным количеством слов всей статьи.

### 3. Средняя длина слова

Метод `avg_word_length` считает среднее количество символов в токенах:

```text
сумма длин токенов / количество токенов
```

Результат округляется до 2 знаков.

### 4. Лексическая плотность

Токены исходного текста анализируются морфологически. К содержательным частям речи относятся:

- `NOUN` — существительные;
- `ADJF` — полные прилагательные;
- `VERB` — глаголы;
- `ADVB` — наречия.

Показатель равен доле таких слов среди всех лемм и округляется до 4 знаков:

```text
число содержательных слов / число всех лемм
```

### 5. Лексическое разнообразие

Метод `lexical_diversity` вычисляет:

```text
число уникальных лемм / число всех лемм
```

Результат округляется до 4 знаков. Используются леммы исходных слов.

### 6. Биграммы частей речи

Для каждого исходного токена определяется часть речи через `pymorphy3`. Для последовательности POS-тегов строятся биграммы (`n=2`). Словарь POS-биграмм фиксирован для всех текстов, а значения представлены относительными частотами, а не абсолютными счётчиками.

В результат записывается полный фиксированный словарь из 289 возможных POS-биграмм:

```text
`POS_1|POS_2: относительная частота`
```

Значения являются нормированными частотами. Если POS-биграмма отсутствует, её значение равно `0.0`. Если в тексте меньше двух POS-тегов, весь словарь состоит из нулей.

## Как из стилометрии формируется вектор признаков

Классификатор не передаёт весь JSON напрямую в модель. Метод `NewsClassifier.extract_features` строит фиксированный вектор:

| Позиции | Признак |
|---:|---|
| 1 | средняя длина предложения |
| 2 | средняя длина слова |
| 3 | лексическая плотность |
| 4 | лексическое разнообразие |
| 5–37 | частоты 33 букв русского алфавита `а`–`я` в фиксированном порядке |
| 38–326 | относительные частоты всех фиксированных POS-биграмм |

Частота каждой буквы всегда находится на одной и той же позиции. POS-биграмма также всегда находится на одной и той же позиции. Отсутствующий признак имеет значение `0.0`.

### Ограничение текущего представления

Проблема переменного смысла признаков устранена: например, частота буквы `о` всегда хранится в позиции, соответствующей `о`, а частота пары `NOUN|VERB` всегда хранится в позиции `NOUN|VERB`. Это делает вектор сопоставимым между статьями и интерпретируемым.

## Как выполняется классификация

В `main.py` вызывается:

```python
accuracy = classifier.train("data/gazeta_analyzed.csv", "data/ria_analyzed.csv")
```

Внутри `train`:

1. Из `data/gazeta_analyzed.csv` извлекаются стилометрические данные, всем строкам назначается метка `0`.
2. Из `data/ria_analyzed.csv` извлекаются данные, всем строкам назначается метка `1`.
3. Данные объединяются в матрицу `X`, метки — в массив `y`.
4. `train_test_split` делит данные на обучающую и тестовую части. Размер тестовой части — `20%` (`test_size=0.2`), используется `random_state=42` и стратификация по классу (`stratify`), чтобы доля классов сохранялась в обеих выборках.
5. На обучающей части обучается `GaussianNB` из scikit-learn — гауссовский наивный байесовский классификатор.
6. На тестовой части считается `accuracy`, то есть доля правильных предсказаний.
7. Состав обеих выборок сохраняется в `data/classifier_split.json`: для каждой новости записываются исходный файл, номер строки, класс и текст. В файл попадают параметры разбиения `random_state` и `test_size`.

Таким образом, классы в текущем коде означают:

- `0` — строка из `data/gazeta_analyzed.csv`, вывод программы называет её «Старая» новость;
- `1` — строка из `data/ria_analyzed.csv`, вывод программы называет её «Новая» новость.

Строго говоря, модель обучается различать не абстрактную «новизну», а два набора данных: «Газета.Ru» против РИА Новости. Источник и временной период смешаны в одном признаке класса, поэтому по результату нельзя надёжно утверждать, что модель распознаёт именно дату новости.

Демонстрационное предсказание в `main.py` берётся из `classifier.test_records[0]`, то есть из сохранённой/сформированной тестовой выборки, а не из обучающих записей. Состав split дополнительно сохраняется в `data/classifier_split.json`.

Для нового текста сначала нужно получить стилометрический JSON того же формата, затем вызвать:

```python
prediction = classifier.predict(stylometry_data)
probabilities = classifier.predict_proba(stylometry_data)
```

`predict` возвращает `0` или `1`, а `predict_proba` — вероятности обоих классов.

## Формат файлов

- `data/ria.csv` — скачанные статьи РИА Новости до стилометрии.
- `data/gazeta.csv` — скачанные статьи «Газеты.Ru» до стилометрии.
- `data/ria_analyzed.csv` — текст и JSON со стилометрическими признаками РИА Новости.
- `data/gazeta_analyzed.csv` — текст и JSON со стилометрическими признаками «Газеты.Ru».
- `data/classifier_split.json` — состав train/test выборок последнего обучения.
- `stylometry.py` — вычисление признаков.
- `classifier.py` — подготовка векторов, обучение и предсказание.
- `recent_news.py` — сбор РИА Новости и извлечение исходного текста.
- `old_news.py` — сбор «Газеты.Ru» и извлечение исходного текста.
- `main.py` — полный сценарий.

## Запуск

Зависимости перечислены в `requirements.txt`. Для запуска полного цикла:

```bash
python main.py
```

При запуске программа задаёт три независимых вопроса:

```text
Парсить новости РИА заново? [д/н]:
Парсить новости Газеты.Ru заново? [д/н]:
Провести стилометрический анализ заново? [д/н]:
```

- Для РИА ответ `д`/`да` запускает новый парсинг и заменяет только `data/ria.csv` после его завершения. Ответ `н`/`нет` использует существующий файл РИА.
- Для «Газеты.Ru» ответ `д`/`да` запускает новый парсинг и заменяет только `data/gazeta.csv` после его завершения. Ответ `н`/`нет` использует существующий файл «Газеты.Ru».
- На третий вопрос `д`/`да` заново выполняется стилометрический анализ обоих выбранных исходных файлов и заменяются `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv`.
- На третий вопрос `н`/`нет` используются существующие результаты анализа без пересчёта.

Это позволяет отдельно обновлять корпус РИА или «Газеты.Ru», а также менять параметры `StylometricAnalyzer` без повторного скачивания новостей. Для каждого источника, для которого выбран ответ `н`, должен существовать соответствующий raw-файл.

Если корпус был создан старой версией программы и содержит уже очищенные или стемизированные тексты, его нужно пересоздать, выбрав `д` для соответствующего источника. В актуальном корпусе `data/ria.csv` и `data/gazeta.csv` поле `text` должно содержать исходный текст статьи.

При новом парсинге исходные CSV сначала записываются во временные файлы внутри `data`. При новом стилометрическом анализе analyzed-CSV также сначала записываются во временные файлы. Существующие файлы заменяются только после успешного завершения соответствующей операции. При ошибке анализа временные analyzed-файлы удаляются, а предыдущие данные сохраняются; при аварийном завершении парсинга временные raw-файлы сохраняются для восстановления прогресса.

При обработке каждой статьи её результат сразу дописывается в соответствующий временный CSV и сбрасывается на диск. Поэтому при сбое уже обработанные статьи остаются во временном файле. Таймаут или другая ошибка загрузки отдельной статьи выводится в журнал, после чего программа пропускает эту статью и продолжает обработку следующих. Если парсинг завершается аварийно, временные файлы не удаляются автоматически: их пути выводятся в консоль, и их можно использовать для восстановления прогресса. Старые рабочие CSV при этом не заменяются.

Для работы парсеров требуется установленный Chrome/Chromium и возможность Selenium запустить браузер в headless-режиме. `webdriver-manager` автоматически подбирает ChromeDriver в используемом сценарии РИА Новости; для «Газеты.Ru» Selenium использует доступный драйвер Chrome. При первом запуске NLTK может загрузить ресурсы `punkt` и `punkt_tab`.

### Матрица режимов запуска

| РИА | «Газета.Ru» | Стилометрия | Результат |
|---|---|---|---|
| `д` | `д` | `д` | Обновить оба корпуса и пересчитать признаки |
| `д` | `н` | `д` | Обновить только РИА и пересчитать признаки обоих источников |
| `н` | `д` | `д` | Обновить только «Газету.Ru» и пересчитать признаки обоих источников |
| `н` | `н` | `д` | Использовать оба сохранённых корпуса и пересчитать признаки |
| `н` | `н` | `н` | Использовать сохранённые корпуса и признаки |

Режим `н`/`н`/`д` предназначен для изменения параметров в `stylometry.py` без повторного скачивания новостей.

## Методологические замечания

- Классификация выполняется на уровне источников/наборов данных, а не на уровне авторов.
- Исходный текст сохраняется с пунктуацией, поэтому границы предложений доступны для `avg_sentence_length`; при этом сами буквенные и POS-признаки рассчитываются по токенам и морфологическим разборам.
- Оба источника используют одинаковую обработку в `StylometricAnalyzer`: NLTK для токенизации предложений и слов и `pymorphy3` для лемматизации/POS-разбора.
- POS-биграммы представлены нормированными частотами, поэтому они меньше зависят от длины текста, чем абсолютные счётчики.
- Деление на train/test выполняется с фиксированным seed и стратификацией по классам, но кросс-валидация в коде не используется.
- Одной `accuracy` недостаточно для полноценной оценки: при несбалансированных классах следует дополнительно смотреть precision, recall, F1 и confusion matrix.
- Если analyzed-файлы были рассчитаны старой версией признаков, их нужно пересчитать через режим `н`/`д`.
- `data/ria_analyzed.csv` и `data/gazeta_analyzed.csv` должны соответствовать текущей версии `stylometry.py`; после изменения признаков их следует пересчитать через режим `н`/`д`.
